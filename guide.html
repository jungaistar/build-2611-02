양식이 달라도 같은 표로 모읍니다

목표 표 구조를 한 번 정하고, 파일마다 열 짝짓기를 확인해 확정합니다. 읽기와 정리는 전부 이 브라우저 안에서 끝나고 파일은 어디로도 올라가지 않습니다.

1. 순서

  1. 목표 표 구조를 정합니다. 화면에서 고치거나, 첫 줄에 열 이름을 적은 양식 엑셀을 올립니다. 둘째 줄에 글자·숫자·날짜·코드 를 적으면 형식이 됩니다.
  2. 정리할 엑셀·CSV·PDF 를 올립니다. 시트마다, PDF 는 쪽마다 표 하나로 읽습니다.
  3. 표를 하나씩 눌러 짝짓기를 확인합니다. 틀린 짝은 고르는 칸에서 바꿉니다.
  4. 「이 표 확정」을 누릅니다. 확정한 표만 결과에 모입니다.
  5. 결과를 엑셀이나 CSV 로 내려받습니다.

2. 표를 읽는 방식

상황처리
여러 시트시트마다 따로 읽고, 짝짓기도 시트마다 따로 정합니다.
병합 셀병합 범위 전체에 왼쪽 위 값을 채웁니다. 채운 값은 「병합 채움」으로 표시합니다.
머리글이 두 줄머리글에서 시작한 병합이 아랫줄까지 내려오거나 가로 병합이 있으면 아랫줄도 머리글로 봅니다. 「규격 / 재질」은 「규격 재질」이 됩니다. (EA) (원) 같은 단위 줄도 머리글에 붙습니다.
제목·업체 정보머리글 위의 「업체명 : 가람정밀」 같은 줄은 문서 정보로 읽어, 열처럼 짝지을 수 있습니다.
합계·메모 줄합계·소계 줄, 값이 한 칸뿐인 줄, 머리글이 반복된 줄은 버리고 사유를 보여 줍니다.
PDF글자의 좌표로 줄과 칸을 나눕니다. 칸이 가장 많은 줄(대개 머리글)을 열 기준으로 삼습니다. 스캔한 그림 PDF 는 글자가 없어 읽지 못합니다.

자동으로 찾은 머리글이 틀리면 「머리글 시작 행」과 「줄 수」를 직접 정하고 다시 읽습니다.

3. 짝짓기 제안의 근거

열 이름과 값 모양을 함께 봅니다. 이름이 같으면 가장 높고, 같은 뜻 낱말(예: Part No.·자재코드 = 품번, Q'ty·발주수량 = 수량)이 다음입니다. 괄호 안 단위는 이름 비교에서 뺍니다. 값 모양이 목표 형식과 맞지 않으면(숫자 열에 글자가 들어 있으면) 점수를 깎습니다.

점수가 높은 짝부터 차례로 묶고, 한 원본 열은 한 목표 열에만 씁니다. 신뢰 「낮음」이나 빈 짝은 꼭 눈으로 확인하세요.

AI 연결은 선택입니다. 키를 넣으면 열 이름과 예시 값 3개만 보내 짝을 묻고, 답은 「AI 초안 — 검토 필요」로 표시합니다. 표에 없는 열을 말한 답은 버립니다.

4. 값 출처 표시

문서에 적힌 값과 도구가 만든 값은 신뢰도가 다릅니다. 결과 표와 엑셀의 「값출처」 시트에 구분해 남깁니다.

  • 표시 없음 — 문서에 적힌 값 그대로
  • 병합 채움 — 병합 범위를 풀어 채운 값
  • 형식 변환 — 「1,250」을 1250 으로, 「26.11.20」을 2026-11-20 으로 바꾼 값
  • 문서 정보 · 시트·파일 이름 · 직접 입력 — 표 밖에서 가져온 값
  • 계산 — 금액이 비어 있어 수량 × 단가로 채운 값

금액이 수량 × 단가와 다르거나, 필수 값이 비었거나, 숫자·날짜로 읽지 못한 값은 「확인할 것」에 나옵니다. 읽지 못한 값은 지우지 않고 원래 글자로 둡니다.

5. 짝짓기 규칙 저장

표를 확정하면 열 이름 기준으로 짝짓기 규칙을 저장합니다. 다음에 열 이름이 60% 이상 겹치는 표를 올리면 그 규칙을 그대로 씁니다. 규칙은 이 브라우저에만 저장되므로, 다른 PC 에서 쓰려면 JSON 으로 내보내고 불러옵니다.

6. 폴더 분류·추출(v1.1)

「폴더 분류」 화면에 폴더를 통째로 올리면 안의 엑셀·CSV·PDF 를 문서 종류별로 나누고, 종류마다 정한 항목을 뽑아 조건에 맞는 행만 남깁니다.

  1. 폴더를 끌어다 놓거나 눌러서 고릅니다. 하위 폴더 경로가 파일 이름 위에 보입니다. 엑셀·CSV·PDF 가 아닌 파일은 「건너뜀」입니다.
  2. 분류 결과에서 근거를 봅니다. 「파일 이름 「견적」 +4 · 본문 「견적서」 +3」처럼 어떤 규칙이 몇 점을 줬는지 나옵니다.
  3. 「확인 필요」(1·2위 점수 차이가 기준 이내)와 「미분류」(최소 점수 미만)는 뽑지 않습니다. 종류를 고르면 그때 뽑습니다. 자동 분류가 틀렸으면 그 파일도 고를 수 있습니다.
  4. 종류별 추출 결과에서 조건에 맞은 행과 뺀 행(사유)을 확인하고 엑셀로 내려받습니다. 종류마다 시트 하나, 그리고 분류표·뺀 행·확인할것·건너뛴 파일 시트가 들어갑니다.

분류 규칙 파일

규칙은 rules/doc-types.json 하나입니다. 화면에서 고쳐 적용하고 내려받을 수 있고, 같은 파일을 로컬 스크립트도 씁니다.

칸뜻
closeMargin1·2위 점수 차이가 이 값 이내면 「확인 필요」
types[].id · name문서 종류의 키와 이름(엑셀 시트 이름이 됩니다)
minScore이 점수에 못 미치면 그 종류가 아닙니다
match.fileName · header · body파일 이름 · 머리글(열 이름) · 본문(모든 칸 글자)에 찾을 낱말과 가중치 { "word": "견적", "weight": 4 }. 정규식은 { "re": "^QT-\\d+", "weight": 3 }. 공백·구두점·대소문자는 가리지 않고, 낱말 하나는 한 번만 셉니다.
fields뽑을 항목 — 표 정리 화면의 목표 열과 같은 모양 { "name", "type": text·number·date·code, "required", "aliases" }. aliases 는 이 종류에서만 쓰는 같은 뜻 낱말입니다.
conditions추출 조건(모두 맞아야 남김) — >= <= > < = != between(날짜·숫자 [시작, 끝]) contains notContains(낱말 하나 또는 목록) notEmpty

Codex 로 폴더를 주기적으로 처리하기

Codex 는 웹페이지 안에서 돌지 않습니다. 리포 루트의 AGENTS.md 가 Codex 작업 지시서이고, Codex 는 로컬 스크립트를 돌립니다. node 만 있으면 되고 npm 설치는 필요 없습니다.

node tools/folder-run.mjs <폴더> --rules rules/doc-types.json --out 결과.xlsx --processed processed.json
  • 콘솔에 분류표(상태·종류·점수·뽑음/뺌·경로·근거)를 찍고, 결과 엑셀은 웹 화면에서 내려받는 것과 같은 시트로 만듭니다.
  • --processed 를 주면 이미 처리한 파일(경로·크기·고친 시각이 같은 것)은 건너뜁니다. 새로 들어온 파일만 처리할 때 씁니다.
  • PDF 는 글자가 든 PDF 만 읽습니다(스크립트도 동봉한 pdf.js 로 읽습니다). 스캔 그림 PDF 는 미분류가 됩니다.
  • 확인 필요·미분류 파일은 스크립트가 뽑지 않습니다. 웹 화면에서 종류를 고르거나, 규칙 파일의 낱말·가중치를 고친 뒤 다시 돌립니다.
  • 예제는 리포의 samples/ 폴더입니다: node tools/folder-run.mjs samples

7. 이번 판에서 하지 않는 것

  • 데이터베이스 자동 등록 — 결과는 엑셀·CSV 로 내려받아 등록합니다.
  • 스캔 이미지 PDF·그림 속 표 읽기(OCR).
  • 폴더 감시·예약 실행 — 주기 처리는 Codex(또는 작업 스케줄러)가 로컬 스크립트를 돌리는 방식입니다.
  • 분류 규칙의 자동 학습 — 낱말·가중치는 사람이(또는 Codex 가) 규칙 파일에서 고칩니다.
